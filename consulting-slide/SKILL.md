# コンサル資料スライド作成（ポンチ絵・16:9画像）

HTML（1280×720）でスライドを組み、`scripts/render.py` で PNG（2560×1440）に書き出す。
1枚の中に、プロセス、比較表、対応表、KPI、ロードマップなどの複数のブロックを組み合わせて、構想や全体像をひと目で伝えるポンチ絵を作る。

## 構成（上から順に）
1. **スライドタイトル**：そのページのテーマを名詞句で書く（例：「3年後の法人営業プロセス像」）。38px・極太・黒・左寄せ。タイトルの上に章ラベルなどは置かない。
2. **キーメッセージ**：そのページの結論を文で書く（例：「〇〇により、△△は“A”から“B”へ変わる」）。20px・標準の太さ（太字にしない）・黒。1行が望ましい。
3. **コンテンツ**：ラベル帯の付いたブロックを縦に積み、必要に応じて横に並べる（下記「ブロックの作り方」）。
4. **核心メッセージの帯**（任意）：最下段に、濃い紫の帯で「核心メッセージ｜〜」を1行で書く。ページ全体で一番伝えたいことを書く。
5. **フッター**：左下に出所（数値を載せた場合は必須）、右下にページ番号。

## ブロックの作り方
`templates/base.html` に部品の CSS を用意してある。ブロックは次の組み合わせで作る。

| 部品 | クラス | 使い方 |
|---|---|---|
| ブロック | `.block` | 薄紫の背景・角丸の区画。中身の種類ごとに1ブロック |
| ラベル帯 | `.block-head` > `.label` + `.label-sub` | 左上の紫の帯（右端は斜めカット）に名前、続けて「― 説明」 |
| カード | `.card` | ブロック内の白いカード。ステップや項目ごとに1枚 |
| 核心カード | `.card.core` + `.ribbon` | そのページの一番の主張にあたる要素。紫の太枠＋濃い薄紫の背景、上に「★〇〇」のリボン |
| カード見出し | `.card-title` | `.badge`（丸に頭文字）＋英語名＋`<small>（日本語）</small>`＋`.kanji`（漢字1字タグ） |
| タグ | `.tag` / `.tag.light` | 「AI主導」「人の独占領域」など役割や属性の丸型ラベル。アイコンを添える |
| 矢印 | `.arrow` / `.arrow.sm` / `.arrow.down` | ステップ間・As-IsからTo-Beへの流れ |
| ループ線 | `.loop` | プロセスの下に、最後から最初へ戻る循環を示す線と説明 |
| 比較表 | `table.cmp` / `table.cmp.to-be` | 行見出し＋内容の2列表。As-Is はグレー、To-Be は薄紫の行見出し |
| 工程の並び | `.steps` > `.step` | 表の上に、工程名を矢印でつないで並べる |
| チェックリスト | `ul.checks` | ✓ 付きの箇条書き |
| 核心メッセージ帯 | `.core-band` | 最下段の濃い紫の帯 |

**ブロックの組み合わせ例**（構想・全体像のページ）
- 上段：プロセス全体（ステップカードを矢印でつなぎ、核心となるステップは `.card.core`、下に `.loop`）
- 中段：現状（As-Is）→ 将来（To-Be）の比較表と、工程の対応表
- 下段：新設KPI、ロードマップ（年次・フェーズごとのタグ＋箇条書きを矢印でつなぐ）
- 最下段：核心メッセージの帯

内容に合わせてブロックの種類と数は変えてよい（体制図、ビフォーアフター、課題→打ち手→効果、など）。

## デザインルール
- **色**：#a100ff の濃淡と、黒・白・グレーだけを使う。赤や青など、ほかの色相は使わない。
  - `#a100ff`：ラベル帯、バッジ、矢印、核心カードの枠
  - `#6b00b0`（濃い紫）：カード見出しの文字、強調テキスト（`.em`）、核心メッセージの帯
  - `#f0e0ff` / `#f8f2ff`（薄紫）：核心カードの背景、ブロックの背景
  - 現状（As-Is）など「古いもの・比較対象」はグレーのラベル帯（`style="background:#777"`）にして、紫の新しいものと対比させる
- **フォント**：ヒラギノ角ゴシック。本文11〜12px、カード見出し14px、ラベル帯15px。10px未満は使わない。
- **密度**：ポンチ絵なので余白を残さず、ブロックで画面を埋める。ただし文章は短く、箇条書きは1項目1行・20字程度にする。
- **情報の具体性**：「数十〜数百案」「LTV・解約率」など、具体的な数値や指標名を入れる。中身のない言葉は使わない。

## イラストとアイコン
- **イラスト**：ステップや登場人物をイメージさせるために、カードごとに1点ずつ入れてよい。高さ80px前後に揃える。unDraw から英語キーワードで検索し、#a100ff に色を置き換えて保存する：
  ```bash
  python3 ~/.claude/skills/consulting-slide/scripts/undraw.py search "data analysis"
  python3 ~/.claude/skills/consulting-slide/scripts/undraw.py get <URL> <出力先>/il1.svg
  ```
  HTML では `<img src="il1.svg">` のように相対パスで読み込む。
- **アイコン**：Lucide のアイコンを、CSS で紫に着色して使う。アイコン名は https://lucide.dev/icons で確認する。
  ```html
  <i class="icon" style="--i:url(https://unpkg.com/lucide-static@0.460.0/icons/users.svg)"></i>
  <span class="icon-circle"><i class="icon" style="--i:url(...)"></i></span>  <!-- 薄紫の丸の中に置く -->
  <i class="icon w" style="--i:url(...)"></i>  <!-- 白（タグの中など） -->
  ```

## AI生成っぽさを避けるためのNG
- グラデーション、ドロップシャドウ、光彩、ぼかし、ガラス風の表現
- 絵文字（★や✓などの記号は可）
- ネオン調の配色、紫以外の色相
- 文字の詰め込みすぎによるはみ出し・不自然な折り返し、要素の重なり
- 部品の大きさや位置がばらばらなこと（同じ種類のカード・バッジ・イラストは大きさと位置を揃える）

## 手順
1. ユーザーからスライドの内容（テーマ、伝えたいこと、構成要素、データ、出所）を受け取る。キーメッセージや核心メッセージが決まっていなければ確認する。
2. ブロック構成を決める（どのブロックをどの段に並べるか、核心となる要素はどれか）。
3. `templates/base.html` をコピーして、`<style>` の部品を使いながらブロックを組む。使わない要素（核心メッセージの帯、コピーライトなど）は削除する。
4. 書き出す：
   ```bash
   python3 ~/.claude/skills/consulting-slide/scripts/render.py slide.html slide.png
   ```
5. Read ツールで PNG を開いて確認し、問題があれば HTML を直して書き出し直す。確認項目：
   - はみ出し、文字の切れ、重なり、不自然な折り返しがないか（特にカード見出しとブロックの下端）
   - 核心となる要素がひと目でわかるか
   - 紫の濃淡とグレー以外の色を使っていないか、上記のNGに当てはまる表現がないか
   - 数値の単位と出所が書かれているか
6. 出力先は、ユーザーの指定がなければカレントディレクトリ。HTML と PNG、イラストの SVG を同じフォルダに保存する（例：`slide_01.html` と `slide_01.png`）。
