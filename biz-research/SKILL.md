# ビジネスモデル調査・企業リサーチ

指定された企業（または業界）について、次の3つを調べてまとめる。

1. **ビジネスモデル**：誰に・何を・誰が・どう稼ぐかを、ビズグラム形式の図にする。
2. **KPIツリー**：売上や利益を、具体的な数値付きで、できるだけ深く分解する。
3. **直近のニュース**：対象の企業・業界に関する最近の動きと、それが示すこと。

出力は、ポンチ絵の PNG（必要な枚数）と、それらをまとめた HTML レポート1ファイル。

## 調査の進め方
- WebSearch と WebFetch で調べる。出所は信頼できる順に使う。
  1. 企業の一次情報：決算短信、決算説明資料、有価証券報告書、統合報告書、中期経営計画、IR のファクトブック
  2. 公的統計・業界団体の統計
  3. 主要な報道（日経、各社のニュースリリースなど）
- 次の項目を集める：
  - 事業内容、セグメント構成、主な顧客、提供価値、主なパートナー・仕入先・販売チャネル
  - 収益源（何から、どの課金形態で稼いでいるか）と、コストの大きな項目
  - 直近の業績（売上・営業利益・成長率）とセグメント別の業績
  - 事業 KPI（会員数・ARPU・解約率・店舗数・既存店成長率・稼働率・受注残など、その事業で開示されているもの）とその推移
- **数値には必ず出所と時点（「FY2025」「2025年9月末」など）を付ける。** 開示がない数値は、開示値から計算した推計にとどめ、計算式を報告書に書く。根拠のない数値は作らない。
- ニュースは直近3か月（少なければ6か月）から5〜8件選ぶ。日付・媒体・URL を控え、ビジネスモデルや KPI への影響（示唆）を1行で付ける。
- **業界を指定された場合**：業界全体のバリューチェーン（メーカー・卸・小売・顧客など）を図にし、各段の代表企業を入れる。KPI ツリーは市場規模を頂点にして分解し（例：市場規模 ＝ 利用者数 × 利用率 × 1人あたりの年間支出）、報告書に主要企業の比較表（売上・利益率・シェア）を加える。

## ビジネスモデル図（ビズグラム）
図解総研の「ビズグラム」のルールで描く。お手本：`examples/bizgram.html` / `examples/bizgram.png`。

- **3×3 のマス目**に主体を置く。
  - 段：上から**利用者の段**（誰に価値を提供するか）、**事業の段**（何を提供するか。主な商品・サービス・リソース）、**事業者の段**（誰が事業を行うか。主なパートナー・関係会社）
  - 中央の列の①顧客・②事業（サービス名）・③事業者と、事業の段の左右の④重要な主体、左下の⑤関係会社までは必ず埋める。ほかのマスは必要なときだけ使う。
- **3つの要素**：主体（ヒト・会社・店舗・アプリ・商品・データなどのアイコン）、矢印（主体の間の関係）、補足（主体や矢印だけでは伝わらない重要な情報。小さなグレーの吹き出し）。
- **5種類の矢印**：線の中央の印で区別する。
  - モノ（丸）：物の流れ
  - 情報（四角）：サービス・技術・データなど無形の価値の流れ
  - カネ（¥）：お金の流れ。金額や料率（手数料30%など）がわかれば書く
  - 行為（印なし）：誰が誰に何をするか
  - 包含（端が黒丸）：小さいほうが大きいほうに含まれる関係
- 事業（②）だけをメインカラーにし、カネの印もメインカラーにして、お金の流れを追えるようにする。
- 図の横に、**収益の仕組み**（売上の式と、売上・原価の内訳）、**ポイント**（起点・定説・逆説：その業界で当たり前とされること＝定説に対して、この事業がどう逆を行くか）、**主な数値**、**矢印の凡例**を置く。
- 事業が複数あり1枚に収まらない場合は、全社の全体像を1枚と、主要な事業ごとの図を1枚ずつ作る。

## KPIツリー
お手本：`examples/kpi-tree.html` / `examples/kpi-tree.png`。

- 頂点は売上高（必要に応じて営業利益）。左から右へ、掛け算（×）か足し算（＋・−）で分解し、分解の記号を枝の分かれ目に置く。子の数値を計算すると親の数値になるように揃える。
- **できるだけ深く分解する**（目安は4階層以上）。最下層は、現場で動かせる指標（CVR、CPA、解約率、客数、客単価、稼働率など）まで下ろす。
- 各ノードに「指標名＋数値＋時点（または前年値・業界平均）」を書く。推計値には「推計」のタグを付ける。
- いちばん効くレバー（感応度が大きい、または改善の余地が大きい指標）だけをメインカラーの枠にし、横のパネルに「注目のレバー」（改善したときの売上・利益へのインパクトの試算）と「読み取れること」を書く。
- 1枚に収まらない場合は、全体像を1枚と、深掘りする枝ごとに1枚ずつ作る。

## 直近のニュース
- 1枚のポンチ絵にまとめる。時系列（左から右、または上から下）にニュースを並べ、各ニュースに日付・見出し・示唆を書き、ビジネスモデルや KPI に効くものだけをメインカラーで強調する。図の形は内容から決めてよい。

## ポンチ絵の作り方
- `~/.claude/skills/ponchi-e/SKILL.md` があれば、それを読み、その構成・デザインルール・手順に従ってすべてのポンチ絵を作る（メインカラーは ponchi-e の `theme.css`）。このスキルのお手本は ponchi-e の `templates/base.html` の `.content` に入れて使う形になっている。
- ponchi-e がなければ、ポンチ絵の PNG は作らない。代わりに、同じ内容の図を HTML（CSS や SVG）で直接レポートの中に描く。

## レポート（HTML 1ファイル）
`templates/report.html` をコピーして、`{{ }}` を埋める。
- **要約**：誰に・何を・どう稼ぐか、業績の現状、最も効く KPI、直近の変化を4項目で。
- **ビジネスモデル**：図、事業の概要の表（誰に／何を／誰が／どう稼ぐ／起点→定説→逆説）、セグメント別の業績の表。
- **KPIツリー**：図、各ノードの数値・時点・区分（開示／推計）・根拠や計算式の表。ツリーのすべてのノードを載せる。
- **直近のニュース**：図、ニュースの一覧（日付・見出しのリンク・媒体・要点・示唆）。
- **出所**：使った資料をすべて、資料名・発行元・日付・URL で並べる。
- 図の枚数に合わせて `<figure>` を増減する。ポンチ絵は同じフォルダの PNG を相対パスで読み込む。

## 手順
1. 対象（企業名・業界名）と、特に知りたい観点を確認する。出力先の指定がなければ、カレントディレクトリに対象名のフォルダを作る（例：`./タイミー/`）。
2. 上記「調査の進め方」に沿って調べ、数値と出所を控える。
3. ビジネスモデル図、KPIツリー、ニュースの順にポンチ絵を作る（ponchi-e の手順で、HTML を書いて PNG に書き出し、Read ツールで確認して直す）。ファイル名は `slide_01.html` / `slide_01.png` から連番にする。
4. `templates/report.html` を出力先に `report.html` としてコピーし、内容を埋める。ponchi-e の `theme.css` も出力先にコピーする（ponchi-e の手順で既にあればそのまま）。
5. 確認する：
   - 図とレポートの数値が一致しているか。KPI ツリーの子の数値から親の数値が計算できるか
   - すべての数値に出所と時点があり、推計には計算式があるか
   - ニュースの日付が直近のものか、リンクが正しいか
6. 出力したファイル（PNG の一覧と `report.html` のパス）と、調査でわからなかった点・推計に頼った点をユーザーに伝える。
