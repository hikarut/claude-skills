# ポンチ絵作成（16:9画像）

HTML（1280×720）でスライドを組み、`scripts/render.py` で PNG（2560×1440）に書き出す。
目指すのは、**1枚に1つの主役の図（メタファー）を大きく置き、その周りに整列した補足情報を添える**洗練されたスライド。ぱっと見で構造がわかり、読み込むと具体的な中身まで伝わる情報量にする。

## 構成（上から順に）
1. **スライドタイトル**：そのページのテーマを名詞句で書く。38px・極太・左寄せ。タイトルの上に章ラベルなどは置かない。
2. **キーメッセージ**：そのページの結論を文で書く。20px・標準の太さ（太字にしない）。1〜2行。
3. **コンテンツ**：そのページの主役となる図を1つ置く。図の形は内容から決める（お手本の形に限らない）。
4. **フッター**：右下にコピーライトとページ番号。数値を載せた場合は左下に出所。

## お手本（仕上がりのイメージ）
`examples/` に、お手本の HTML（`<body>` の中身）と完成画像（PNG）がある。お手本は**仕上がりの品質・トーン・情報量の目安**であり、図の形をこの4つに限るものではない。**作り始める前に、内容に近いお手本の PNG を Read ツールで開いてトーンをつかむ。** 内容がお手本の形に合うときはその HTML を流用してよい。

| お手本 | ファイル | 向いている内容 |
|---|---|---|
| 放射図 | `hub.html` / `hub.png` | 中心となる概念と、それを構成する要素・関係するもの。左右のパネルで立場ごとの価値と主な活用を説明 |
| 流れ図 | `flow.html` / `flow.png` | インプット → 主役のサービス・仕組み → アウトプット。サービスや構想の概要。下段に要素ごとの補足（データ・活用シーン・効果）を置く |
| レベル図 | `levels.html` / `levels.png` | 成熟度・スキルレベル・段階と、対象者や提供プランの対応 |
| タイムライン | `phases.html` / `phases.png` | 進め方・ロードマップ・研修やプロジェクトの工程。最下段に工程ごとの成果物を置く |

お手本の形に合わない内容は、内容に合った図を新しく組む。例：比較（2〜3列の対比）、2×2 マトリクス、ビフォーアフター、循環図、ピラミッド、ベン図、ウォーターフォール図、体制図、課題→打ち手→効果、プロフィールなど。`templates/base.html` の部品を使い、下記のデザインルールに沿って、お手本と同じトーンに仕上げる。

## デザインルール
- **1枚1メタファー**：主役の図は1つだけ。2つ目の図を並べない。
- **情報量**：主役の図だけで終わらせず、補足情報を添えて具体性を出す。目安は次のとおり。
  - 図の各要素（ステップ・円・工程など）に、1〜2行の短い説明を付ける
  - 主役の図の下か横に、補足の帯やパネルを置く（主なデータ、活用シーン、効果、成果物、対象者など）。補足は主役の要素の真下・真横に揃えて置き、どの要素の補足かがわかるようにする
  - 補足は、ピル型の小見出し＋チップ（`.chip`：小さなグレーのラベル）や、3項目程度の箇条書きで示す
- **余白**：情報を増やしても、要素の間隔は詰めすぎない。補足の帯は点線（`.dashed-h`）で主役の図と区切り、図全体が上下左右の中央付近に来るように配置する。
- **色**：
  - メインカラーは `theme.css` の `--main` で決まる（既定は `#a100ff`）。HTML の中で色コードを直接書かず、`var(--main)` や下記の変数を使う
  - メインカラーは「主役」にだけ使う。中心の円、本題の工程の矢羽根、主役のプラン、本文中の強調語（`.em`）など
  - 主役ではない要素は、チャコール（`#333`）、グレー（`#d9d9d9` / `#f0f0f0`）、メインカラーの淡色（`var(--tint)` など。メインカラーから自動で作られる）で描く
  - 本題の範囲は淡色の面（`.soft`）で囲み、前後の工程や比較対象はグレーや淡色にして強弱をつける
  - メインカラー以外の色相は使わない
- **文字**：主要な説明は16〜18px、図の中のラベルは16〜24px、補足情報（ステップの説明・チップ・箇条書き・成果物）は14〜15px。14px未満は使わない（小見出しの添え字のみ11〜13px可）。1つの説明は2〜4行に収め、意味の切れ目で `<br>` を入れて改行位置を整える。強調語（`.em`）が行をまたいで分かれないようにする。
- **形**：角丸の面（`.soft`）、細い線の大きな円（`.ring`）、点線の区切り（`.dashed-h` / `.dashed-v`）、ピル型のラベル（`.pill`）、矢羽根（`.chev`）を使う。
- **ラベル**：濃いグレーのピル（`.pill`）を基本にし、主役だけメインカラーのピル（`.pill.main`）にする。

## イラストとアイコン
- **アイコン**：Lucide のアイコンを、グレーの細い線で使う（主役のみ `.main` でメインカラー）。アイコン名は https://lucide.dev/icons で確認する。
  ```html
  <i class="icon" style="--i:url(https://unpkg.com/lucide-static@0.460.0/icons/users.svg)"></i>
  ```
- **イラスト**：人物や場面を見せたいときだけ、1枚に1〜2点まで。大きな円（`.ring`）の中に置くなど、図の一部として使う。unDraw から英語キーワードで検索し、メインカラーに色を置き換えて保存する（`--color` を省略すると `theme.css` の色になる）。お手本のイラスト（`examples/il_*.svg`）を使うときも `recolor` で色を合わせる：
  ```bash
  python3 ~/.claude/skills/ponchi-e/scripts/undraw.py search "team"
  python3 ~/.claude/skills/ponchi-e/scripts/undraw.py get <URL> <出力先>/illust.svg [--color #RRGGBB]
  python3 ~/.claude/skills/ponchi-e/scripts/undraw.py recolor ~/.claude/skills/ponchi-e/examples/il_act.svg <出力先>/il_act.svg [--color #RRGGBB]
  ```

## NG（AI生成っぽさ・野暮ったさを避ける）
- 主役の図だけで中身の薄いページ／逆に、小さな文字の多用やブロックを隙間なく敷き詰めるレイアウト
- メインカラーの多用（主役以外までメインカラーにする）
- グラデーション、ドロップシャドウ、光彩、ぼかし、ガラス風の表現
- 絵文字（★などの記号は可）
- 要素ごとに色付きのアイコンを並べること
- はみ出し、文字の切れ、要素の重なり、1〜2文字だけが次の行に送られる不自然な改行

## 手順
1. ユーザーからスライドの内容（テーマ、伝えたいこと、構成要素、データ、出所）を受け取る。キーメッセージが決まっていなければ確認する。メインカラーの指定があれば控えておく（指定がなければ `theme.css` の色を使う）。
2. 内容から主役の図の形（メタファー）を決める。あわせて、トーンの目安として近いお手本の `examples/*.png` を Read ツールで開いて確認する。
3. `templates/base.html` と `theme.css` を出力先にコピーする。メインカラーの指定があれば、コピーした `theme.css` の `--main` をその色に書き換える（スキル側の `theme.css` は書き換えない）。`base.html` のコピーをもとに、`.content` の中に図を組む。お手本と同じ形なら `examples/*.html` の中身を流用して書き換えてよい。お手本のイラストを使う場合は、その SVG も出力先にコピーする。
4. 書き出す：
   ```bash
   python3 ~/.claude/skills/ponchi-e/scripts/render.py slide.html slide.png
   ```
5. Read ツールで PNG を開いて確認し、問題があれば HTML を直して書き出し直す。確認項目：
   - はみ出し、文字の切れ、重なり、不自然な改行がないか
   - 主役の図がひと目でわかり、メインカラーが主役だけに使われているか
   - 余白と情報量のバランス（図が上や左に偏っていないか、空いた領域が目立っていないか）
   - キーメッセージと図の内容が食い違っていないか
6. 出力先は、ユーザーの指定がなければカレントディレクトリ。HTML と PNG、`theme.css`、イラストの SVG を同じフォルダに保存する（例：`slide_01.html` と `slide_01.png`）。
