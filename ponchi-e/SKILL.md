# ポンチ絵作成（16:9画像）

HTML（1280×720）でスライドを組み、`scripts/render.py` で PNG（2560×1440）に書き出す。
目指すのは、**1枚に1つの主役の図（メタファー）を大きく置き、その周りに整列した補足情報を添える**洗練されたスライド。ぱっと見で構造がわかり、読み込むと具体的な中身まで伝わる情報量にする。

## 構成（上から順に）
1. **スライドタイトル**：そのページのテーマを名詞句で書く。40px・極太・左寄せ。スライドの上端から 34px 空ける。タイトルの上に章ラベルなどは置かない。
2. **キーメッセージ**：そのページの結論を文で書く。22px・標準の太さ（太字にしない）。1〜2行。タイトルとの間は 10px、その下のコンテンツとの間は 30px 空ける（`base.html` の設定どおり。詰めない）。`<br>` で改行せず、ヘッダーの右端（左右の余白は `base.html` の設定どおり）まで使って自然に折り返す。折り返しは文節の切れ目で自動的に行われるが、語の途中で分かれた場合は、その語句を `<span class="nw">` で囲んで分かれないようにする。
3. **コンテンツ**：そのページの主役となる図を1つ置く。図の形は内容から決める（お手本の形に限らない）。
4. **フッター**：右下にコピーライト（ページ番号は付けない）。数値を載せた場合は左下に出所。

## お手本（仕上がりのイメージ）
`examples/` に、お手本の HTML（`<body>` の中身）と完成画像（PNG）がある。お手本は**仕上がりの品質・トーン・情報量の目安**であり、図の形をこれらに限るものではない。**作り始める前に、内容に近いお手本の PNG を Read ツールで開いてトーンをつかむ。** 内容がお手本の形に合うときはその HTML を流用してよい。

| お手本 | ファイル | 向いている内容 |
|---|---|---|
| 放射図 | `hub.html` / `hub.png` | 中心となる概念と、それを構成する要素・関係するもの。左右のパネルで立場ごとの価値と主な活用を説明 |
| 流れ図 | `flow.html` / `flow.png` | インプット → 主役のサービス・仕組み → アウトプット。サービスや構想の概要。要素ごとの補足（データ・活用シーン・効果）を、各要素の真下に置く |
| レベル図 | `levels.html` / `levels.png` | 成熟度・スキルレベル・段階と、対象者や提供プランの対応 |
| タイムライン | `phases.html` / `phases.png` | 進め方・ロードマップ・研修やプロジェクトの工程。最下段に工程ごとの成果物を置く |
| 比較表 | `compare.html` / `compare.png` | 2〜3案（プラン・選択肢）の比較。おすすめの案だけメインカラーにする |
| 事例カード | `cases.html` / `cases.png` | 導入事例・実績・プロフィールなど、見出し＋説明＋画像を同じ重みで3つ並べる |
| 3つの理由 | `reasons.html` / `reasons.png` | 理由・ポイント・特長を3つ並べ、それぞれの結論の一言でキーメッセージにつなげる |
| 目標と施策 | `goal.png` | 数値目標のグラフ（主役の年だけ強調）と、それを実現する施策のパネルを左右に並べる |
| 詳細ロードマップ | `gantt.png` | 領域（行）× 四半期（列）の表に、工程の箱と領域ごとの進め方を並べる |
| 短期・中長期のプラン | `plans.png` | 矢羽根で期間を分け、期間ごとに施策のカード（見出し帯＋箇条書き＋図や画像）を置く |

`goal.png`・`gantt.png`・`plans.png` は画像だけのお手本（HTML はない）。構成・情報量・文字の強弱の参考にし、色・角丸・章ラベル・ページ番号・グラデーションなどは下記のデザインルールに従う。

**お手本は構成と配置の参考であり、文字の大きさと余白は下記の「文字の大きさ」「余白」のルールを優先する。** お手本の HTML には、今のルールより小さい文字（14〜15px）や広い余白が残っている箇所がある。流用するときは、文字を一段大きくし、余白を詰めて書き換える。

お手本の形に合わない内容は、内容に合った図を新しく組む。例：2×2 マトリクス、ビフォーアフター、循環図、ピラミッド、ベン図、ウォーターフォール図、体制図、課題→打ち手→効果など。`templates/base.html` の部品を使い、下記のデザインルールに沿って、お手本と同じトーンに仕上げる。

## グラフ・定番の図解（24選）
`references/charts.md` に、資料でよく使うグラフ・図解24種（ベン図、2×2、ロジックツリー、散布図、ヒートマップ、複合グラフ、帯グラフ、ファネル、スイムレーン、同心円など）と、それぞれが向いている内容・描き方をまとめてある（見た目は `references/charts_1〜3.png`）。
- 図の形を決めるときに、`references/charts.md` の「選び方の目安」を見て、内容に合うものがあれば積極的に使う。数字の比較・推移・構成比・関係・流れ・範囲などは、文章やカードで並べるより、合ったグラフや図解の方が一目で伝わる。
- どれが最適かは、一番言いたいこと（比較・変化・関係・流れ・構造など）から選ぶ。合うものがなければ使わない。グラフを入れること自体を目的にしない。
- 使うときは、形の参考として該当する画像を Read ツールで開いてから描く。

## メッセージと関係性（情報を羅列しない）
ポンチ絵は情報の一覧ではなく、1つの主張を見せる図にする。図を組む前に次の3点を決める。
- **一番言いたいこと（so what）を1つに絞る。** キーメッセージは「何が書いてあるか」ではなく「だから何か」を書く（例：「〇〇の動向」ではなく「ボトルネックは発見から検証と修正に移っている」）。図の中で一番目立つ要素が、キーメッセージの結論と一致するようにする。
- **強調するのは、その結論にあたる部分だけ。** メインカラーの塗り（白抜き文字）や枠、一番大きな数字を、結論の1か所（多くても1つの行・列）に集める。同じ重みで並ぶ要素がすべて同じ色・同じ大きさになっていたら、強弱がついていない。比較対象や前提はグレー・淡色にして下げる。
- **要素の関係を、配置と矢印で見せる。** 要素を並べる前に、要素どうしの関係（原因→結果、変化→問題→打ち手、前提→比較→差、工程の繰り返し、分岐など）を決め、その関係が見える配置にする。
  - 原因→結果・変化→打ち手：左から右へ並べ、間を矢印でつなぐ。列の上に「何が変わるか → 何が問題になるか → 何をすべきか」のような列見出しを付けると、因果が読める
  - 複数の観点 × 因果：観点を行、因果の段階を列にした表にし、結論の行だけを強調する
  - 数値の比較：前提（全体の結果）→「何が違ったか」の矢印→比較の順に置き、差が最も大きい項目を大きく・強調し、それ以外は小さく・淡くする
  - 繰り返し・改善のループ：最後の工程から最初の工程へ戻る矢印を描き、矢印の上に何を繰り返すかを書く
  - 次の段階に進む条件：工程と次の段階の間の矢印に、進む条件（例：「正答率を確かめて任せる」）を書く
- 矢印は線（2px）＋三角の先端で描き、結論につながる矢印だけメインカラー、それ以外はグレーにする。

## デザインルール
- **1枚1メタファー**：主役の図は1つだけ。2つ目の図を並べない。
- **情報量**：主役の図だけで終わらせず、補足情報を添えて具体性を出す。目安は次のとおり。
  - 図の各要素（ステップ・円・工程など）に、1〜2行の短い説明を付ける
  - 補足（主なデータ、活用シーン、効果、成果物、対象者など）は、主役の図の要素の中か、その真下・真横に揃えて置き、どの要素の補足かがわかるようにする
  - **図の下に、別の帯を足さない。** 全幅の点線で区切って、調査概要・関連キーワード・まとめのチップや箇条書きを並べた帯は、デザインも内容も弱くなる。伝えたい補足は主役の図の中に入れ、入らない情報は載せない
  - 補足は、ピル型の小見出し＋チップ（`.chip`：小さなグレーのラベル）や、3項目程度の箇条書きで示す
- **余白（詰め込みすぎず、無駄な空きも残さない）**：文字を大きくしたうえで、要素のまわりに息つぎの余白を残す。目指すのは、余白が1か所（パネルの下など）に固まらず、カードの内側と要素の間に均等に散らばっている状態。
  - **文字の量を絞る。** コンテンツ（タイトル・キーメッセージ・出所を除く）の文字数は **200〜250字** を目安にし、300字を超えない（`render.py` が警告する）。入りきらないときは、文字を小さくしたり余白を削ったりせず、説明を短くするか、重要度の低い情報（4つ目以降の例、補足の補足）を削る
  - **カードの内側の余白（上下 18px・左右 24px）は削らない。** 文字が入りきらないときは、余白を詰めるのではなく文字やカードを減らす。カードは `.card.fill` で縦に伸ばし、中身を上下中央に置いて、残りの空きを各カードの内側に均等に分ける（`render.py` が、内側の余白が狭いカードと、余白を確保できないほど詰まったパネルを警告する）
  - 1つのパネルに置くカードは 3〜4つまで、1つのカードの文字は見出し＋2〜3行まで。カードの中にさらに箱を入れ子にしない
  - 余白を1か所に残さない：パネルの下に 40px 以上の空きが固まっている場合は、カードを `flex:1` にして空きを均等に分けるか、文字・数字を大きくする（帯や要素を足して埋めない）
  - 主役の図はコンテンツの領域いっぱい（上下左右とも）に置く。下や右に大きな空きを残さない
  - **余白の段階をそろえる。** 外側ほど広く、内側ほど狭くし、同じ段階の余白はスライド全体で同じ値にする。値は `base.html` の変数と部品（`.panel`・`.card`・`.card.fill`）で決まっているので、スライドごとに `padding` や `gap` を書き換えない
    | 段階 | 値 | 変数 |
    |---|---|---|
    | キーメッセージとコンテンツの間 | 30px | （`.content` の `margin-top`） |
    | パネルどうしの間 | 24px（矢印を挟む場合は矢印の幅 44〜72px） | `--gap-panel` |
    | パネルの内側 | 24px（上下左右とも） | `--pad-panel` |
    | カードの内側 | 上下 18px・左右 24px | `--pad-card` |
    | カードどうしの間 | 14px | `--gap-card` |
    | 見出しと本文の間 | 6px | `--gap-text` |
  - パネルの見出し（`.pill`）、カードの左端、カードの中の文字の左端を、それぞれ縦にそろえる。中央ぞろえのカード（数字のカードなど）と左ぞろえのカードを1つのパネルに混ぜない
  - 列見出し（「何が起きたか」など）は、パネルの外に1行足すより、パネルの中の見出し帯（`.pill`）にまとめて縦の空きを減らす
  - 1つのカードの中で、文字が左に寄って右半分が空いている場合は、カードを細くするか、数字を右に大きく置く
- **色**：
  - メインカラーは `theme.css` の `--main` で決まる（既定は `#3b5af4`）。HTML の中で色コードを直接書かず、`var(--main)` や下記の変数を使う
  - メインカラーは「主役」にだけ使う。中心の円、本題の工程の矢羽根、主役のプラン、本文中の強調語（`.em`）など
  - 主役ではない要素は、チャコール（`#333`）、グレー（`#d9d9d9` / `#f0f0f0`）、メインカラーの淡色（`var(--tint)` など。メインカラーから自動で作られる）で描く
  - グラフの濃淡（ヒートマップ、ファネル、矢羽根、積み上げの区分など）は、薄い順に `var(--tint-2)`（5%）・`var(--tint)`（10%）・`var(--tint-3)`（17%）・`var(--tint-4)`（30%）・`var(--tint-5)`（50%）・`var(--main)` を使う
  - 本題の範囲は淡色の面（`.soft`）で囲み、前後の工程や比較対象はグレーや淡色にして強弱をつける
  - メインカラー以外の色相は使わない
- **文字の大きさ**：スライドは縮小して見られることが多いので、文字は大きめにする。**最小は16px**（出所・コピーライトのみ13px）。16px未満の文字は使わない（`render.py` が警告する）。
  | 役割 | 大きさ | 太さ |
  |---|---|---|
  | 主役の数値（KPI・結論の数字） | 48〜64px（単位は数字の半分）。72px を超えない | 極太（800） |
  | 比較・補足の数値（グラフの値、表の数字） | 32〜40px（単位は数字の半分） | 太字 |
  | パネル・カードの見出し、図の主なラベル | 22〜26px | 太字 |
  | 本文・説明・箇条書き | 18〜20px | 標準 |
  | 補足（ステップの説明・チップ・注記・目標値などの添え書き） | 16〜17px | 標準（注記はグレー） |
  | ピル（ラベル） | 17〜18px | 太字 |
  図の中の1つの説明は2〜3行に収め、意味の切れ目で `<br>` を入れて改行位置を整える（キーメッセージには `<br>` を入れない）。文字を大きくして入りきらないときは、文字を小さくするのではなく、説明を短く言い換えるか、重要度の低い情報を削る。強調語（`.em`）が行をまたいで分かれないようにする。
- **文字の強弱**：すべてを同じ大きさ・太さで並べず、役割ごとにはっきり差をつける。隣り合う段階の差は、見出しと本文で 4px 以上、数字と本文で 2〜3.5倍を目安にする。数字を大きくしすぎると、数字だけが浮いて周りが窮屈に見えるので、主役の数字でも本文の 3.5倍（64px 前後）までにとどめる。
  - **数字は大きくする。** 数字が言いたいことの中心になるページでは、数字を文章の中に埋めず、`.num`（`.xl` 60px／`.l` 48px／`.m` 34px）で独立させて大きく置き、単位は `<small>` で数字の半分にする（例：`<span class="num xl">954<small>%</small></span>`）。主役の数字1つだけをメインカラーにし、それ以外の数字はチャコールにする
  - 数字の比較（前年→今年、目標→実績）は、比べる元の数字を小さく・グレーに、結論の数字を大きく・太くする
  - 見出し（パネル・カードの見出し帯、図の主なラベル）は太字にし、その下の本文より 4px 以上大きくする（例：見出し 22〜24px、本文 18px）
  - 太字にする文字は、周りの標準の太さの文字より少し大きくする。同じ大きさのまま太字にするだけにしない
  - 補足（注記・単位・添え字）は小さく、グレー（`var(--sub)`）にして本文と区別する
  - キーメッセージは、結論の語句だけを `.em` で強調する（1〜2か所）
- **形**：角丸の面（`.soft`）、細い線の大きな円（`.ring`）、ピル型のラベル（`.pill`）、矢羽根（`.chev`）を使う。
- **角丸の統一**：四角いオブジェクトはすべて角丸にし、半径は2種類にそろえる。
  - 面・カード・パネル（`.soft`、`.soft-gray`、カードの外枠など）：`var(--r)`（16px）
  - 小さな箱・見出し帯・画像の枠・タグ・枠線の箱（`.outline`）：`var(--r-sm)`（8px）
  - 表の列や上下に連結した帯は、外側の角だけを丸める。円・ピル・矢羽根はそのままでよい
- **区切り**：要素の区切りは余白と面（`.soft` / `.soft-gray`）で表し、点線や罫線の区切り線は引かない。点線（`.dashed-h` / `.dashed-v`）は、タイムラインの期間の境目のように、図の意味として必要な場合だけ使う。
- **ラベル**：濃いグレーのピル（`.pill`）を基本にし、主役だけメインカラーのピル（`.pill.main`）にする。

## イラストとアイコン
- **アイコン**：Lucide のアイコンを、グレーの細い線で使う（主役のみ `.main` でメインカラー）。アイコン名は https://lucide.dev/icons で確認する。
  ```html
  <i class="icon" style="--i:url(https://unpkg.com/lucide-static@0.460.0/icons/users.svg)"></i>
  ```
- **イラスト**：人物や場面を見せたいときだけ、1枚に1〜2点まで（事例カードのように同じ重みの項目に1点ずつ添える場合は、項目の数まで）。大きな円（`.ring`）の中に置くなど、図の一部として使う。unDraw から英語キーワードで検索し、メインカラーに色を置き換えて保存する（`--color` を省略すると `theme.css` の色になる）。お手本のイラスト（`examples/il_*.svg`）を使うときも `recolor` で色を合わせる：
  ```bash
  python3 ~/.claude/skills/ponchi-e/scripts/undraw.py search "team"
  python3 ~/.claude/skills/ponchi-e/scripts/undraw.py get <URL> <出力先>/illust.svg [--color #RRGGBB]
  python3 ~/.claude/skills/ponchi-e/scripts/undraw.py recolor ~/.claude/skills/ponchi-e/examples/il_act.svg <出力先>/il_act.svg [--color #RRGGBB]
  ```

## NG（AI生成っぽさ・野暮ったさを避ける）
- 主役の図だけで中身の薄いページ／逆に、小さな文字の多用やブロックを隙間なく敷き詰めるレイアウト
- 文字を大きくしたまま情報を減らさず、カードの中で文字が上下の縁に近づいている窮屈なレイアウト
- 主役の数字を 72px を超える大きさにして、数字だけが浮いているレイアウト
- 文字が小さく、パネルの下やカードの右側に使われていない空きが残っているレイアウト（空きは文字・数字を大きくして埋める）
- 数字を本文と同じ大きさで文章の中に埋めること、すべての数字を同じ大きさで並べること
- 情報をカードや箇条書きで同じ重みに並べただけで、要素の関係（因果・比較・流れ）も、一番言いたいことも見えない図
- 図の下に全幅の点線を引き、その下にチップや箇条書きの帯を足すこと。カードの中を点線で区切ること
- メインカラーの多用（主役以外までメインカラーにする）
- グラデーション、ドロップシャドウ、光彩、ぼかし、ガラス風の表現
- 絵文字（★などの記号は可）
- 角丸のオブジェクトと直角のオブジェクトの混在、角丸の半径のばらつき
- 要素ごとに色付きのアイコンを並べること
- はみ出し、文字の切れ、要素の重なり、1〜2文字だけが次の行に送られる不自然な改行

## 手順
1. ユーザーからスライドの内容（テーマ、伝えたいこと、構成要素、データ、出所）を受け取る。キーメッセージが決まっていなければ確認する。メインカラーの指定があれば控えておく（指定がなければ `theme.css` の色を使う）。
2. 「メッセージと関係性」に沿って、一番言いたいこと・強調する1か所・要素の関係を決め、それが見える主役の図の形（メタファー）を決める。グラフや定番の図解の方が伝わる内容なら、`references/charts.md` から選ぶ。あわせて、トーンの目安として近いお手本の `examples/*.png` を Read ツールで開いて確認する。
3. `templates/base.html` と `theme.css` を出力先にコピーする。メインカラーの指定があれば、コピーした `theme.css` の `--main` をその色に書き換える（スキル側の `theme.css` は書き換えない）。`base.html` のコピーをもとに、`.content` の中に図を組む。お手本と同じ形なら `examples/*.html` の中身を流用して書き換えてよい。お手本のイラストを使う場合は、その SVG も出力先にコピーする。
4. 書き出す：
   ```bash
   python3 ~/.claude/skills/ponchi-e/scripts/render.py slide.html slide.png
   ```
   書き出したあと、文字の大きさ・余白・はみ出しを自動で確かめ、問題があれば `WARN:` を出す。Playwright のブラウザが別の場所にある環境では、`CHROMIUM_PATH=<chrome のパス>` を付けて実行する。
5. Read ツールで PNG を開いて確認し、問題があれば HTML を直して書き出し直す。確認項目：
   - はみ出し、文字の切れ、重なり、不自然な改行がないか
   - キーメッセージが途中で改行されず、右端まで使って折り返されているか
   - 四角いオブジェクトがすべて角丸で、半径がそろっているか
   - `render.py` の警告（`WARN:`）が出ていないか。16px未満の文字、内側の余白が狭すぎるカード・パネル、大きすぎる数字（72px超）、文字数の多さ（300字超）、詰まりすぎのパネル（カードの内側の余白を確保できない）、パネルの下の空き、コンテンツの下の空き、はみ出しを警告する。警告が出たら直して書き出し直す
   - 文字が十分に大きいか（本文18px以上、補足16px以上）。縮小表示でも読めるか
   - 文字に強弱がついているか（主役の数字が本文の2〜3.5倍で目立ち、浮いていないか。見出しが本文より4px以上大きいか）
   - 余白のバランス：窮屈でないか（カードの中で文字が縁に近くないか）、逆に空きが1か所に固まっていないか
   - 主役の図がひと目でわかり、メインカラーが主役だけに使われているか
   - 図の下に点線と補足の帯を足していないか、不要な区切り線がないか
   - キーメッセージと図の内容が食い違っていないか
   - 情報の羅列になっていないか（一番言いたいことがひと目でわかり、そこだけが強調され、要素の関係が矢印や配置で読めるか）
6. 出力先は、ユーザーの指定がなければカレントディレクトリ。HTML と PNG、`theme.css`、イラストの SVG を同じフォルダに保存する（例：`slide_01.html` と `slide_01.png`）。
