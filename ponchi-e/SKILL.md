# ポンチ絵作成（16:9画像）

HTML（1280×720）でスライドを組み、`scripts/render.py` で PNG（2560×1440）に書き出す。
目指すのは、**文字を読まなくても、絵と配置で言いたいことが伝わる**スライド。1つの主張を、1つの図とイラスト・アイコンで見せ、文字はそれを補う。

## 構成
1. **スライドタイトル**：テーマを名詞句で（40px・極太）。
2. **キーメッセージ**：結論を1文で（22px・標準の太さ・1〜2行）。結論の語句1〜2か所だけ `.em` で強調する。`<br>` は入れない。2行になるときは、最後の行が数文字（強調語だけなど）にならないよう言い換えて長さを調整する。
3. **コンテンツ**：主役の図を1つ。
4. **フッター**：右下にコピーライト、数値や記事を使ったら左下に出所。

タイトル・キーメッセージ・コンテンツの間の余白とフッターの位置は `templates/base.html` で決まっているので変えない。

## 手順
1. **伝えることを決める。** 一番言いたいこと（so what）を1つに絞り、キーメッセージにする（「〇〇の動向」ではなく「だから何か」）。キーメッセージが決まらなければユーザーに確認する。
2. **型を選ぶ。** 下の「型の選び方」で、まずお手本（`examples/`）の型に当てはまるかを見る。当てはまる型があれば、その `examples/<型>.html` をコピーし、構成（配置・部品・要素の数）を保ったまま中身を書き換える。お手本のどれにも当てはまらないときだけ、新しい形を組む。**数字が出てくるときは、あわせて下の「数字の見せ方」で図を選ぶ。**
3. **絵を選ぶ。** 下の「絵（イラストとアイコン）」に沿って、主な要素ごとにイラストかアイコンを決める。
4. **組む。** `templates/base.html` と `theme.css` を出力先にコピーする。型を使うときは、`base.html` の `<body>` の中身を `examples/<型>.html` の中身に置き換えて書き換える（`<style>` もそのまま使う）。使った同梱イラストもコピーする。型がないときは `.content` の中に図を組む。メインカラーの指定があれば、コピーした `theme.css` の `--main` を書き換える。
5. **書き出して確かめる。**
   ```bash
   python3 ~/.claude/skills/ponchi-e/scripts/render.py slide.html slide.png
   ```
   `WARN:` が出たら直して書き出し直す（文字の小ささ、絵がない、数字があるのにグラフがない、間延びしたカード、詰まりすぎ、空きの固まり、はみ出し、文字数の多さ、大きすぎる文字・数字を警告する）。Playwright のブラウザが別の場所にある環境では `CHROMIUM_PATH=<chrome のパス>` を付ける。最後に PNG を Read ツールで開き、下の「仕上がりの確認」を見る。
6. HTML・PNG・`theme.css`・（使った場合は）イラストの SVG を同じフォルダに保存する（指定がなければカレントディレクトリ）。

## 型の選び方
スライドの構成は、まずお手本の型から選ぶ。毎回ゼロから新しいレイアウトを組むと、構成がぶれて見慣れない図が増える。

| 内容 | 型（`examples/`） |
|---|---|
| サービス・仕組み・構想の概要（何を入れて、何をして、何が得られるか） | `flow` |
| 導入事例・実績・取り組みを、同じ重みで2〜3つ紹介する（カードごとに unDraw のイラスト） | `cases` |
| 中心となる概念と、それを取り巻く要素・関係者 | `hub` |
| 成熟度・段階・レベルと、対象者やプランの対応 | `levels` |
| 進め方・ロードマップ・スケジュール | `phases` |
| 2〜3案（プラン・選択肢）の比較 | `compare` |
| 理由・特長・ポイントを3つ並べる（カードごとに unDraw のイラスト） | `reasons` |
| 数値目標と施策、詳細ロードマップ、短期・中長期のプラン | `goal`・`gantt`・`plans`（画像のみ。PNG を見て組む） |

- **選ぶ前に、候補の型の PNG を Read ツールで開いて見比べる。** 1つに決めたら、その HTML を土台にする。
- **型を使うときは構成を保つ。** 配置と部品（円・中央のパネル・帯矢印・下段の補足、見出し帯・画像・成果の欄など）はそのままにし、文言・数字・アイコン・イラストを内容に合わせて差し替える。要素の数は内容に合わせて増減してよい（3つを2つや4つにするなど）。
- **新しい形を組むのは、どの型にも当てはまらないときだけ。** 例：課題→打ち手→効果の因果、ビフォーアフター、数字が主役のグラフ（`references/charts.md`）。その場合も、お手本と同じ部品（`.panel`・`.card`・`.badge`・`.pill`・`.link`）とトーンで組む。
- 毎日などで続けて作るときは、同じ型ばかりにならないよう、内容に合う範囲で型を使い分ける。

## 絵（イラストとアイコン）
文字とカードだけのスライドは分かりにくい。図の主な要素には、**その要素そのものを表す絵**を添えて、文字を読まなくても何の話かわかるようにする。
- **イラスト**：具体的なもの・場面を表す要素（入力・出力、システムや仕組み、事例など）に、要素の左や中に大きく（高さ 120〜200px）置く。1枚に1〜3点（事例カードのように同じ重みの項目に添える場合は項目の数まで）。同じ重みの要素には、同じ大きさ・同じ位置でそろえる。
- **飾りのイラストは使わない。** パネルの見出しの横や、空いた隅を埋めるためのイラストは不要。要素と対応しないイラストを置かない。
- **アイコンの絵**：工程・手順・リストの各項目、抽象的な要素には、Lucide のアイコンを付ける。**番号や文字だけで並べず、項目ごとに内容を表すアイコンを付ける**（例：整理 `list-checks`、比較 `scale`、推定 `search`、実行 `play`）。大きく見せたい要素は、アイコンを淡色の円に入れた `.badge`（`--s` で 40〜96px。主役は `.main`、グレーの面の上は `.white`）にする。名前は https://lucide.dev/icons で、具体的なものを表す名前を探す。
  ```html
  <span class="badge" style="--s:48px"><i class="icon" style="--i:url(https://unpkg.com/lucide-static@0.460.0/icons/scale.svg)"></i></span>
  ```
- イラストは unDraw から英語キーワードで探し、メインカラーに色を合わせて保存する。HTML では `<img class="illust" src="il_data.svg" style="height:140px">` のように読み込む。
  ```bash
  python3 ~/.claude/skills/ponchi-e/scripts/undraw.py search "data server"
  python3 ~/.claude/skills/ponchi-e/scripts/undraw.py get <URL> <出力先>/il_data.svg
  ```
  unDraw に接続できないときは、同梱のイラスト（`examples/il_*.svg`：`il_collect` データ・サーバー、`il_act` 人と画面、`il_finance` ビジネスパーソンとグラフ、`il_retail` 買い物、`il_telecom` スマートフォン、`il_segments` 顧客の区分、`il_options` 選択肢、`il_warning` 警告）を `recolor` で色を合わせて使う。
  ```bash
  python3 ~/.claude/skills/ponchi-e/scripts/undraw.py recolor ~/.claude/skills/ponchi-e/examples/il_collect.svg <出力先>/il_collect.svg
  ```

## 数字の見せ方（数字があるときは必ず）
数字をカードや文章に並べるだけにしない。**`references/charts.md` のグラフ・図解で見せる。** 選んだら、その図の画像（`references/charts_1〜3.png`）を Read ツールで開いて形を確かめ、元の `charts_1〜3.html` の `<svg>` を写して数値とラベルを書き換える。

| 数字の内容 | 使う図（charts.md の番号） |
|---|---|
| 人数・人の割合（10人中3人、〇名のうち〇名） | 絵グラフ（15）：人型 `.person` を並べ、該当分だけメインカラー |
| 段階ごとに絞り込まれる数（母数 → 候補 → 決定） | ファネル（19）：各段に数と率を書く |
| 2〜5項目の量の比較 | 棒グラフ：長さを値に比例させる |
| 前後の変化（前年→今年、導入前→後） | 2本の棒、または小さい元の数字 → 大きい結果の数字 |
| 推移 | 折れ線・複合グラフ（14） |
| 構成比 | 帯グラフ（16）・ツリーマップ（21） |
| 達成率・目標に対する進捗 | ゲージ（13） |

- **図は値に正しく比例させる。** 棒の長さ・面積は値に比例させる。値の差が大きすぎて比例させると見えなくなる場合は、ファネルの段（同じ幅ずつ細くなる形）にして、長さで比べさせない。比例していない棒を並べない。
- **結論の数字は、図のどこからどこへの変化かを示す。** 「〇%減」「〇倍」などは、元の値と結果の値を矢印でつなぎ、その矢印に数字を添える。図の中でメインカラーにする場所と、結論の数字を一致させる。
- 人型は `base.html` の `.person` を使う（`<span class="people"><span class="person on"></span>…</span>`）。10〜20人で割合を表し、何人中何人かを大きな数字で添える。

## 文字の強弱
文字は3段階以上に分け、ひと目で「見出し → 中身 → 補足」の順に読めるようにする。最小は16px（出所・コピーライトのみ13px）。

| 役割 | 大きさ | 太さ |
|---|---|---|
| 主役の数字（`.num`） | 48〜64px（単位は半分の大きさ） | 極太 |
| 比較の数字 | 32〜40px | 太字 |
| パネルの見出し（`.panel > .pill`） | 20〜22px | 太字 |
| カードの見出し、図のラベル | 22〜26px | 太字 |
| 本文・説明 | 18〜20px | 標準 |
| 補足・注記・チップ | 16〜17px | 標準（注記はグレー `var(--sub)`） |

- 各カードは「太い見出し（一言の結論）＋短い説明（1〜2行）」にする。見出しと説明が同じような大きさ・太さで並ばないようにする。
- 数字は文章に埋めず、`.num` で独立させて大きく置く。主役の数字1つだけをメインカラーにする。数字の前後の文字（約・減・倍・名・% など）は `<small>` で数字の半分の大きさにする（例：`<span class="num xl"><small>約</small>89<small>%減</small></span>`）。どの文字も 72px を超えない。
- 入りきらないときは、文字を小さくせず、説明を短くするか情報を削る。コンテンツの文字数は 200〜250字が目安（300字まで）。
- 説明は意味の切れ目で `<br>` を入れて改行し、1〜2文字だけが次の行に送られないようにする。

## 余白
- 余白の値（パネルの内側 24px、カードの内側 上下18px・左右24px、カードどうし 14px など）は `base.html` の部品（`.panel`・`.card`）で決まっている。スライドごとに `padding` や `gap` を書き換えない。
- **無駄な空きを残さない。** カードの中で文字が小さく固まり、上下や右に大きな空きがあるのは間延び。カードを縦に引き伸ばして埋めず、イラストや数字を大きくする、説明を1行足す、カードを横に並べるなどして、中身でカードを満たす。
- **詰め込まない。** カードの内側の余白は削らない。1パネルのカードは3〜4つまで。
- 主役の図はコンテンツの領域いっぱいに置き、下や右に大きな空きを残さない。図の下に補足の帯や点線を足さない。

## 色と形
- メインカラー（`var(--main)`）は結論にあたる1か所だけに使う：主役の要素、結論につながる矢印、主役の数字、`.em`。それ以外はチャコール・グレー・淡色（`var(--tint)` など）。図の中で一番目立つ要素が、キーメッセージの結論と一致するようにする。
- 本題の範囲は淡色の面（`.soft`）、補助はグレーの面（`.soft-gray`）。ラベルは濃いグレーのピル（`.pill`）、主役だけ `.pill.main`。
- 要素の関係は配置と矢印で見せる（左から右、上から下）。矢印は `.link`（線＋三角）で、結論につながるものだけメインカラー。
  - **矢印は、結ぶ要素から出す。** 複数の要素から1つの要素へ渡すときは、それぞれの要素から矢印を出す（2つのカードから右のパネルへ渡すなら、各カードの中央の高さから1本ずつ）。
  - 矢印と文字をそろえる：矢印は結ぶ要素の中央の高さに置き、矢印のラベルは矢印の真上に中央そろえで置く。
- 角丸は2種類：面・パネル・カードは `var(--r)`（16px）、小さな箱・ラベル・画像の枠は `var(--r-sm)`（8px）。
- 色コードを直接書かない。メインカラー以外の色相、グラデーション、影、絵文字、区切りの罫線や点線は使わない。

## 仕上がりの確認
- 文字を読まなくても、絵と配置で何の話かわかるか。要素と対応しない飾りのイラストがないか
- 矢印がそれぞれの要素から出ていて、矢印と文字の位置がそろっているか
- 当てはまる型があるのに、ゼロから別の構成を組んでいないか
- 一番目立つところが、キーメッセージの結論と一致しているか
- 見出し・本文・補足・数字に、はっきりした強弱があるか
- 間延びしたカードや空きの固まりがなく、逆に窮屈でもないか
- はみ出し、文字の切れ、重なり、不自然な改行がないか
