# X の投稿文作成

テーマを受け取り、参考記事を探して中身を読み、ユーザー本人が書いたとわかる言い回しで X の投稿文を作る。記事の URL を受け取った場合は、記事を探さずにその記事で投稿文を作る（下の「URL を渡された場合」）。

## 使うファイル
- `references/style.md`：過去の投稿の分析。書き手、言い回し、投稿の型、反応の傾向、よく引用する出所、お手本。**毎回最初に読む。**
- `data/posts.csv`：過去の投稿 1,369 件と反応（2023年7月〜2026年11月）。列は次のとおり。
  - `date`、`text`
  - `kind`：information＝記事の紹介、opinion＝意見、diary＝日記
  - `target`：SQL／AI／データ分析／ビジネスパーソン
  - `image`、`repost`
  - 反応：`imp`（インプレッション）、`like`、`rt`、`reply`、`profile`、`link`、`eng`、`eng_rate`
  - `intent`：狙い・仮説のメモ
  - `review`：投稿後の振り返り
- `scripts/count.py`：投稿文のウェイトを数える。
- `scripts/append_sheet.py`：投稿文をスプレッドシートの C 列（ツイート）に追加する（Google Sheets API）。設定は `config.json`。
- `scripts/update_posts.py`：`data/posts.csv` を、スプレッドシートから直接作り直す（Google Sheets API）。設定は `config.json`。

## 文字数の制限
- 上限は **280ウェイト**。半角英数字・半角記号・半角スペース・改行は1、日本語・全角文字・絵文字は2、URL は長さにかかわらず1本23として数える。
- **目安は 230〜280。** 過去の投稿の中央値は 250〜265 で、短い投稿は伸びにくい。日本語だけなら全角でおおむね 115〜140字、URL を1本入れると本文はおおむね 100〜125字になる。
- 書いたら必ず `scripts/count.py` で数える。280 を超えたら削り、230 を大きく下回ったら記事の具体的な中身を足す。
  ```bash
  python3 ~/.claude/skills/x-post/scripts/count.py <<'EOF'
  投稿文
  EOF
  ```

## 手順
1. **過去の投稿を理解する。**
   - `references/style.md` を読む。
   - `data/posts.csv` からテーマに関係する投稿を探す。テーマの語と、その周辺の語で `text` を検索する。
   - 関係する投稿のうち、インプレッションの上位と、直近の投稿を10件ほど読む。そこから次の4点をつかむ。
     - このテーマで、どんな記事をどんな切り口で紹介してきたか
     - どれが伸びたか
     - `intent`（狙い）と `review`（振り返り）に何が書かれているか
     - すでに紹介した記事（URL）はどれか
2. **参考記事を探す。**
   - WebSearch で、テーマと過去の投稿で伸びた切り口に近い記事を探す。
   - 出所と記事の種類は `references/style.md` の「参考にする記事」に合わせる。
     - 優先する出所：zenn・note・speakerdeck・ベンダーの解説・海外の記事
     - 優先する種類：概念の整理、比較、実装デモ、失敗から学ぶ記事、調査の数字がある記事
     - 単なる製品発表や提携のニュースは優先度を下げる。
   - 記事は「けんすう理論」の優先順位で選ぶ（`references/style.md` の「発信の方針」）。まず「みんなが知りたくて、みんなが知らない情報」を探す。「知らないけど興味がない情報」は選ばない。
   - 原則として直近1〜2か月の記事にする。
   - `data/posts.csv` にすでにある URL・記事は除く。
3. **記事を読む。**
   - 候補を WebFetch で開き、中身を最後まで読む。見出しや要約だけで書かない。
   - 一番効いている指摘（引用できる一言、数字、整理の枠組み）を控える。
   - 開けない記事、有料で読めない記事は使わない。
4. **投稿文を書く。**
   - 型と言い回しは `references/style.md` に従う。ポイントは次のとおり。
     - 常体で書く。絵文字とハッシュタグは使わない。
     - 冒頭で何の記事かを言い切る。
     - 記事の指摘を「」で引用して評価する。
     - URL は本文の後ろに置く。
   - 指定がなければ、記事の紹介（information）を3案作る。意見（opinion）を頼まれたら、記事の論点に、書き手の経験（データ分析組織の立ち上げ、SQL の研修・本）や現場の実感を重ねる。
   - 書いた内容が記事の中身と合っているかを見直す。記事にない数字や主張を足さない。
5. **確認する。**
   - すべての案を `scripts/count.py` で数え、230〜280 に収める。
   - URL が記事の実物と一致しているかを確かめる。
6. **出力する。** 案ごとに次を出す。
   - 投稿文（そのまま貼れる形で、コードブロックに入れる）
   - ウェイト（`count.py` の結果）
   - 参考記事：タイトル、媒体、公開日、URL
   - 区分（information／opinion）とターゲット（SQL／AI／データ分析／ビジネスパーソン）：過去の記録と同じ分け方で
   - 狙い：過去の投稿の反応から、なぜこの記事・切り口を選んだか（1〜2行）
   - 最後に、おすすめの案と投稿時間（8時台）を1行で
7. **スプレッドシートに追加する。**
   - どの案を追加するかをユーザーに確認する。
   - 選ばれた案を、1案ずつテキストファイルに書き出してから追加する。
     ```bash
     python3 ~/.claude/skills/x-post/scripts/append_sheet.py -f post1.txt [post2.txt ...]
     ```
   - 追加したシート名と行番号をユーザーに伝える。C 列以外（日付・区分など）は書き込まない。
   - `config.json` やサービスアカウントの鍵がない、ライブラリが入っていないなどで失敗した場合は、エラーの内容を伝え、README の「スプレッドシートの設定」を案内する。

## URL を渡された場合
ユーザーが記事の URL を貼ったら（URL だけの場合も含む）、その記事の投稿文を作る。上の手順のうち、次のように変える。
- **手順1**：`references/style.md` を読み、記事のテーマに関係する過去の投稿を `data/posts.csv` から探して読む。同じ URL がすでに投稿されていたら、その日付と反応をユーザーに伝える（受けるネタの再投稿は方針上問題ないので、止めずに伝えるだけにする）。
- **手順2（記事を探す）は行わない。**
- **手順3**：渡された記事を WebFetch で最後まで読む。開けない・有料で読めない場合は、その旨を伝えて止まる（推測で書かない）。
- **手順4**：URL 1本につき投稿文を1案作る。URL が複数あれば、それぞれ1案ずつ作る。ユーザーが「何案か」と頼んだら、切り口（引用する指摘、数字、要点の箇条書きなど）を変えて複数案を作る。
- **手順5〜7**：同じ。ウェイトを数えて 230〜280 に収め、出力し、どの案をスプレッドシートに追加するか確認して追加する。出力の「狙い」には、過去の投稿の反応から見たこの記事の伸びやすさ（出所・テーマ・記事の種類）を書く。

## 過去の投稿データの更新
「過去の投稿データを更新して」と言われたら、スプレッドシートから `data/posts.csv` を作り直す。
- 名前が「ツイートリスト_」で始まるシートをすべて読み、本文が入っている行を書き出す。毎回シートの内容で作り直すので、反応の数値の更新や、シート上での修正・削除もそのまま反映される。
  ```bash
  python3 ~/.claude/skills/x-post/scripts/update_posts.py
  ```
- 投稿文を作る前にも、`data/posts.csv` が古ければ（最後の投稿日が直近でなければ）更新してから使う。
- 更新したら件数を伝える。投稿の傾向が大きく変わっていれば、`references/style.md` の分析（反応の傾向・テーマ・お手本）も見直す。
